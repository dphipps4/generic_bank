# From 80% to 100%

What AI wrote, what we changed, what we threw away or left out, what we'd cut next, and what running this unattended still needs.

## What AI produced

Nearly all of it. The author wrote the prompts that produced the plan: the key architectural requirements, the evidence, where behavior is deterministic and where an agent decides, and the details of the software factory and its stages. Claude wrote the plan, the code, the tests and most of these docs, in many small pull requests. The author reviewed and edited the plan heavily, reviewed most of the PRs and approved every merge. The author also had to step in: to correct mistakes in the implementation, to cut designs that were overbuilt or too complex, to challenge claims that weren't accurate, and to pull the work back to the plan when it drifted. The memory design comes from lessons learned building earlier software factories.

## The biggest change: the crawler, rebuilt from evidence

The first crawler passed its tests, and it was wrong in a way the tests couldn't show. It found pages and controls in a JSON model of the DOM, and it was written by an AI that had read the bank's own source, so it knew things no teller could see. The first factory had the same flaw at one remove: the Supervisor dictated each step to the Scout, then drafted a profile of the bank's words, a glossary, from its memory of the run, and some of its claims were guesses no action had proved.

We threw both away and rebuilt from what is rendered:
- **The runtime:** Playwright and Chrome, seeing first, then clicking. It finds fields by drawn labels and buttons by drawn names, and never reads the bank's code.
- **The evidence** ([`docs/evidence/bank-1`](evidence/bank-1/README.md)): bank 1 walked through its web UI, 29 times, with every hazard forced. Walking it found seven problems the synthetic tests never had.
- **Bank 1's crawler:** a route written from those frames, every row citing one, and one loop that replays any route.
- **The factory:** the Scout now acts and writes the same kind of route from what it did, each entry checked in code. The Supervisor judges every action from its picture instead of dictating it. A person approves the result.

The new crawler is a fraction of the old one's size. And you can follow every row back to a picture of the page it came from, which is the part we care about most.

## What else we changed or hardened

The first drafts read well and failed in ordinary ways. The classic ones are a CSS selector, a retried submit and a model that could move money. These are the ones this build actually hit:

- **A submit never pressed twice.** An unclear result now waits 10 seconds, then reads the account's history. Found once means done; anything else goes to a person.
- **Fresh machines.** A check that runs `just setup` and `just up` on a clean machine found two bugs no other test could see: Postgres was called ready while its first-start server was still running, and two blank model keys counted as the same secret.
- **Browser fingerprint.** Chrome presents itself as Chrome on a Mac. Inside Docker, though, the banks are plain HTTP, and there Chrome leaves out headers every real browser sends, so bank 2 turned the crawler away as a bot. The tests ran the banks on the local machine, where Chrome does send them, so only a walkthrough on a fresh copy caught it. Chrome now treats the banks as secure sites, as it would over HTTPS.
- **Swagger UI for the API.** The API's own spec drives a page where you can read and try every call, signed in with OAuth2. Curl works too.
- **Evidence.** Every step of a run and of the factory's crawl records a picture of the page and the page's JSON: only visible elements, no shadow DOM, and every personal value painted out with the same rule the text follows. The Scout works from this evidence; the Supervisor uses it to correct the Scout and to find the root cause of failures. The Console shows the evidence beside each step.
- **Hazards that were too frequent.** The fake banks' random hazards (an outage, a lost session, a pop-up) were drawn on every page, and a run loads about 20 pages, so about one run in three needed a person. Now about 3% of runs meet one, and none fires on the transfer pages. The crawler handles the ones it can with fixed code, with no agent: retries, matching the page's words, starting again from home.
- **A username treated as a secret.** The guard refuses to type a stored secret into the wrong field, and the username 0412 counted as one, so a sign-in code containing 0412 froze the bank. Now only the password is checked, and usernames are at least 8 characters.
- **Docs that claimed what the code never did.** A line-by-line review of every doc against the code found confident claims about safety that nothing implemented: a locked operator freezing the bank's sign-ins, a reminder after 24 hours, logs that were "scrubbed". Each now says what the code really does. AI writes plausible prose fast; only checking it against the code catches this.
- **A learned route in the bank's own words.** In service, the guard judges every step by the kind of screen and the control's name in the allowlist's words. A route that named screens and controls only in the bank's words would have been refused there. Now the Scout gives each screen its kind and says which allowed control a press stands for, and the guard judges every step while the Scout learns. A route the guard would refuse never reaches the gate.
- **A person's time on the factory's clock.** Each goal's clock paused while a person gave a sign-in code, but the run's limit kept counting, so a slow code took time from the agents. Now a person's time counts against no clock, and the run has 30 minutes of the agents' own time.
- **One task at a time.** A transfer waiting for approval held the Runner's only slot, so every other task waited behind it. The Runner now works on two at a time.
- **Node 26.** Chrome's installer quit halfway under it, leaving a browser that died on launch. The tests found it; a newer installer fixed it.

## What we threw away

- **Vault.** SOPS already held every secret and no app read from Vault, so it moved to Part 2.
- **A demo agent.** AI added a third role beside the Scout and the Supervisor, a Demo Agent, for "chatting with the API". Nobody asked for it. Curl and Swagger UI show and test the API just as well.
- **Chainguard images.** Smaller in theory; in practice bigger, and two base images instead of one.
- **Most of the tests.** The suite had grown to 109 files. It now keeps one proof per thing the system ships, and master runs it in four parts at once. A pull request runs only the tests it touches, and a change to the docs runs none.
- **Memory's extra machinery.** Facts, a curated catalog, attempts, hypotheses, promotion rules and a hash-chained change log, none of which anything used. Memory now keeps runs and lessons, and fixed rules for disputing and retiring them.
- **A second model protocol.** The factory's gateway spoke Anthropic's protocol as well as OpenAI's. It now speaks one, through OpenRouter, and OpenAI directly still works.
- **The bank 1 walk script.** It recorded the evidence once. The evidence stays; the script went.
- **Mock mode.** Recorded model answers replayed in CI passed off a script as a model. Every factory test now runs with no model, or a fake one behind the real gateway, and live runs are live.
- **Banks 3 and 4, and Download Statements.** Two tasks and one target app make the case; two banks show the reuse across tenants.
- **make,** replaced by just.

## What we left out

- **Transfers over a bank's manager threshold.** The run stops, and a person finishes it.
- **The factory for bank 1.** Its route is maintained by hand from its evidence.
- **Desktop apps.** The runtime drives a browser. A desktop runtime could take its place, because the routes and the loop that replays them don't depend on the browser.

## What we'd cut next

Memory's local embedding model. For a sample this size, Postgres alone could match lessons worded alike. We kept it because lessons from different banks say the same thing in different words, and that's the case memory is for.

## What unattended use still needs

- Names masked inside other words. A name the run knows is now masked as a whole word, so a word that merely contains it stays readable; a name run together with other letters, as in an email address, is no longer hidden by the name rule, and would need a rule of its own.
- Running in the cloud: more than one runner, behind a WAF, with Vault for secrets.
- The rest of the guardrails: each page classified, a member scope, pacing.
- The bank's manager-approval page as a row of its own, so transfers over the threshold finish without a person taking over.
- Escalations that show a person the run's real inputs. Today they're masked, so taking over a transfer means asking the caller for the member and amount.
- Every hazard forced against a deployed stack on a schedule, not just one of each kind in the tests.
- A step that scrolls until an item is drawn, for the long virtualized lists single-page apps use.
- Cut-outs no wider than their label. Some of bank 2's learned cut-outs take in a few pixels beside the label, so a change next to a label breaks them.
- The factory learning more banks of the same vendor, with a real budget.
