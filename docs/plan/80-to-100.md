# From 80% to 100%

What AI wrote, what we changed, what we threw away, what we'd cut next, and what running this unattended still needs.

## What AI produced

Nearly all of it. The author wrote the prompts that generated the plan, outlining key architectural requirements, evidence, determinsistic vs agent behavior, and the precise details of the software factory and stages of processing; Claude wrote the plan, the code, the tests and the majority of these docs, working through many small pull requests. The author heavily reviewed and edited the plan, reviewed most of the PRs, and approved merges. The author did have to step in to correct errors in the implementation, as well as correcting overdesign or overcomplex solutions, challenging inaccurate representations and deviation from the original plan. Learnings from prior software factories drove the memory implementation.

## What we changed or hardened

The first drafts read well and failed in ordinary ways. The plan's §T.4 lists the classic ones (a CSS selector, a retried submit, a model that could move money). These are the ones this build actually hit:

- **A submit never pressed twice.** An unclear result now waits 10 seconds, then reads the account's history. Found once means done; anything else goes to a person.
- **Fresh machines.** A check that runs `just setup` and `just up` on a clean machine found two bugs no other test could see: Postgres was called ready while its first-start server was still running, and two blank model keys counted as the same secret.
- **Browser fingerprint.** Docker was misconfigured, and the default HTTP request fingerprint triggered faults in the bank's browser test. Chrome in now configured to send HTTP request headers and user-agent that match a Mac running Chrome.
- **API generates HTML using Swagger.** Easier to read and gets us a testable interface that still suports oAuth2.
- **Evidence.** Every stage of the software factorys crawl now records a screenshot, in grayscale, and the JSON of the page, minus any isVisible=false elements (no shadow DOM), wiith all PII marked out as white-with-asterisk. The scout reasons and can use the evidence, but the supervisor uses the evidence to correct the scout, as well as do RCA on failures. The evidence is surfaced in the admin UI via small buttons next to each stage.
- **Node 26.** Chrome's installer quit halfway under it, leaving a browser that died on launch. The tests found it; a newer installer fixed it.
- **Recorded model runs** checked the model's name, so changing the model broke every replay. They now ignore it.

## What we threw away

- **Vault.** SOPS already held every secret, and no app read from Vault, so that was moved to Part 2.
- **A demo agent.** AI added an additional persona to Scout and Operator, called Demo Agent, to support "chatting with the API". Curl and Swagger UI now allow viewing and testing of the API as required.
- **Chainguard images.** Smaller in theory; in practice bigger, and two base images instead of one.
- **Most of the tests.** The suite had grown to 109 files and 43 minutes. It now keeps one proof per thing Part 1 ships, and a change runs only the tests it touches.
- **Dropped make** and replaced it with just.

## What we'd cut next

Memory's local embedding model. For a sample this size, Postgres alone could match lessons worded alike. We kept it because lessons from different banks say the same thing in different words, and that's the case memory is for. 

## What unattended use still needs

The plan's Part 2. Mainly: moving to cloud, the rest of the guardrails (each page classified, member scope, pacing), the factory onboarding a new bank live with a real budget, Vault and a Cloudflare edge, and the full hazard matrix running nightly against a deployed stack.
