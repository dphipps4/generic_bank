# From 80% to 100%

What AI wrote, what we changed, what we threw away, what we'd cut next, and what running this unattended still needs.

## What AI produced

Nearly all of it. The author wrote the prompts that produced the plan: the key architectural requirements, the evidence, where behavior is deterministic and where an agent decides, and the details of the software factory and its stages. Claude wrote the plan, the code, the tests and most of these docs, in many small pull requests. The author reviewed and edited the plan heavily, reviewed most of the PRs and approved every merge. The author also had to step in: to correct mistakes in the implementation, to cut designs that were overbuilt or too complex, to challenge claims that weren't accurate, and to pull the work back to the plan when it drifted. The memory design comes from lessons learned building earlier software factories.

## What we changed or hardened

The first drafts read well and failed in ordinary ways. The classic ones are a CSS selector, a retried submit and a model that could move money. These are the ones this build actually hit:

- **A submit never pressed twice.** An unclear result now waits 10 seconds, then reads the account's history. Found once means done; anything else goes to a person.
- **Fresh machines.** A check that runs `just setup` and `just up` on a clean machine found two bugs no other test could see: Postgres was called ready while its first-start server was still running, and two blank model keys counted as the same secret.
- **Browser fingerprint.** Chrome presents itself as Chrome on a Mac. Inside Docker, though, the banks are plain HTTP, and there Chrome leaves out headers every real browser sends, so banks 2 to 4 turned the crawler away as a bot. The tests ran the banks on the local machine, where Chrome does send them, so only a walkthrough on a fresh copy caught it. Chrome now treats the banks as secure sites, as it would over HTTPS.
- **Swagger UI for the API.** The API's own spec drives a page where you can read and try every call, signed in with OAuth2. Curl works too.
- **Evidence.** Every step of a run and of the factory's crawl records a screenshot in grayscale and the page's JSON: only visible elements, no shadow DOM, and every piece of PII covered by a white box with asterisks. The Scout works from this evidence; the Supervisor uses it to correct the Scout and to find the root cause of failures. The Console shows the evidence beside each step.
- **Hazards that were too frequent.** The fake banks' random hazards (an outage, a lost session, a pop-up) were drawn on every page, and a run loads about 20 pages, so about one run in three needed a person. Now a run-stopping hazard reaches about 1 run in 240, and none ever fires on the transfer pages.
- **A username treated as a secret.** The guard refuses to type a stored secret into the wrong field, and the operator ID 0412 counted as one, so a sign-in code containing 0412 froze the bank. Now only the password is checked, and usernames are at least 8 characters.
- **Docs that claimed what the code never did.** A line-by-line review of every doc against the code found confident claims about safety that nothing implemented: a locked operator freezing the bank's sign-ins, a reminder after 24 hours, logs that were "scrubbed". Each now says what the code really does. AI writes plausible prose fast; only checking it against the code catches this.
- **One task at a time.** A transfer waiting for approval held the Runner's only slot, so every other task waited behind it, for up to 15 minutes. The Runner now works on two at a time.
- **Node 26.** Chrome's installer quit halfway under it, leaving a browser that died on launch. The tests found it; a newer installer fixed it.
- **Recorded model runs** checked the model's name, so changing the model broke every replay. They now ignore it.

## What we threw away

- **Vault.** SOPS already held every secret and no app read from Vault, so it moved to Part 2.
- **A demo agent.** AI added a third role beside the Scout and the Supervisor, a Demo Agent, for "chatting with the API". Nobody asked for it. Curl and Swagger UI show and test the API just as well.
- **Chainguard images.** Smaller in theory; in practice bigger, and two base images instead of one.
- **Most of the tests.** The suite had grown to 109 files and 43 minutes. It now keeps one proof per thing Part 1 ships, a change runs only the tests it touches, and a change to the docs runs none.
- **make,** replaced by just.

## What we'd cut next

Memory's local embedding model. For a sample this size, Postgres alone could match lessons worded alike. We kept it because lessons from different banks say the same thing in different words, and that's the case memory is for.

## What unattended use still needs

The plan's Part 2. Mainly: moving to the cloud, the rest of the guardrails (each page classified, member scope, pacing), the factory onboarding a new bank live with a real budget, Vault and a Cloudflare edge, and the full hazard matrix running nightly against a deployed stack.
