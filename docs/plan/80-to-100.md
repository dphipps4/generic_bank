# From 80% to 100%

What AI wrote, what we changed, what we threw away, what we'd cut next, and what running this
unattended still needs.

## What AI produced

Nearly all of it. Claude wrote the plan, the code, the tests and these docs, working through many
small pull requests. A person set the direction, reviewed every merge and made the calls below.

## What we changed or hardened

The first drafts read well and failed in ordinary ways. The plan's §T.4 lists the classic ones (a
CSS selector, a retried submit, a model that could move money). These are the ones this build
actually hit:

- **A submit never pressed twice.** An unclear result now waits 10 seconds, then reads the
  account's history. Found once means done; anything else goes to a person.
- **Fresh machines.** A check that runs `just setup` and `just up` on a clean machine found two
  bugs no other test could see: Postgres was called ready while its first-start server was still
  running, and two blank model keys counted as the same secret.
- **Node 26.** Chrome's installer quit halfway under it, leaving a browser that died on launch.
  The tests found it; a newer installer fixed it.
- **Recorded model runs** checked the model's name, so changing the model broke every replay.
  They now ignore it.

## What we threw away

- **Vault.** SOPS already held every secret, and no app read from Vault. It moved to Part 2.
- **A demo agent.** Curl and Swagger UI prove the API just as well.
- **Chainguard images.** Smaller in theory; in practice bigger, and two base images instead of
  one.
- **Most of the tests.** The suite had grown to 109 files and 43 minutes. It now keeps one proof
  per thing Part 1 ships, and a change runs only the tests it touches.
- **make,** for just.

## What we'd cut next

Memory's local embedding model. For a sample this size, Postgres alone could match lessons
worded alike. We kept it because lessons from different banks say the same thing in different
words, and that's the case memory is for.

## What unattended use still needs

The plan's Part 2. Mainly: the rest of the guardrails (each page classified, member scope,
pacing), the factory onboarding a new bank live with a real budget, Vault and a Cloudflare edge,
and the full hazard matrix running nightly against a deployed stack.
