# Appendix C: technology

| Part | Choice | Why |
|---|---|---|
| Language | **TypeScript** (strict), **Node 26**, ESM, npm workspaces | One language for the banks, the API, the runner, the factory and memory; types carry the task contract end to end |
| HTTP | **Fastify** | Small and schema-first |
| API contract | **zod** in [`packages/contracts`](../packages/contracts/src/index.ts) | One schema validates, types and documents every input, result and code |
| API docs and tools | **OpenAPI** from the zod schemas, **Swagger UI**; `GET /tools` gives agents tool definitions | Generated from the code, so they can't drift from it |
| API auth | **OAuth2**: client credentials, a one-time code, rotating refresh tokens | Only hashes stored; a reused refresh token revokes its family |
| Browser | **Playwright** with Chrome, presenting as Chrome on a Mac | Real input and frames; the bank runs its own JavaScript |
| Perception | The masked **screenshot**, the visible **accessibility tree** per frame, controls by role and position | What a person sees, never the bank's source; no script of ours runs in the page |
| Masking and pictures | **pngjs**, text positions from the browser's own layout | One rule for every view: money and names hidden whole, numbers keep their last four |
| Crawler | A **table** per bank (data) and **one loop** for every bank | A bank is data; the loop is tested once |
| Durable runs | **DBOS Transact** on Postgres | A library, not a server: durable waits for a person, idempotent runs |
| Database | **PostgreSQL 16** with **pgvector**; **Prisma** migrations | One engine for runs, the registry, the factory and memory's lessons |
| Pictures | A shared Docker volume | No object store needed on a laptop |
| Console | **AdminJS** for API clients, users and the audit log; our own pages for the inbox, runs, approvals and freezes | A person's work in one place |
| Factory agents | **pi**, one session per role, through our **metering gateway** to **OpenRouter** | The model is config; the gateway holds spend to $25 a run and $150 a week |
| Default model | `meta/muse-spark-1.3` through OpenRouter, for the Scout and the Supervisor (both low effort) | Reads pictures and calls tools, with a long context |
| Memory | Its own service; **bge-small-en-v1.5** embeddings on CPU | Lessons worded differently still match; no API cost |
| Secrets | **SOPS** with **age**; env vars through a zod schema that fails closed | Encrypted in git, generated by `just setup` |
| Logs | **pino** JSON | Requests only, never member details; the PII suite searches them |
| Tests | **vitest**: unit, browser against the real banks, workflows on in-process Postgres | One runner for all of it |
| Checks | **ESLint**, **Prettier**, **dependency-cruiser**, **gitleaks** | Import rules keep the crawler from the bank's code; no secrets in history |
| CI | **GitHub Actions** | A pull request runs only what it touches, in one to three minutes; master runs everything in under four |
| Running it | **Docker Compose**, **just** | One command for each thing a person does |
